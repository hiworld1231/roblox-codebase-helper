# Studio panel design

One native developer control panel, not a website. The user's primary action is
Connect this project, followed by a reliable view of index freshness. Backup is a
secondary action; automatic persistence is stated once. Product controls do not expose
transport tokens, JSON schemas, implementation logs or fabricated context percentages.

Direction: calm Studio utility, theme-aware surfaces, clear type hierarchy and one blue
primary action. One project surface groups identity, read-only state and real metadata
counts. All actions have text labels and >=42 px target height; layouts own the
vertical flow. A scrolling dock widget supports narrow/short Studio panes. Body text
wraps instead of shrinking. Source coverage is labelled as fetched code, not indexing
progress toward an automatic whole-game read. No decorative imagery is needed.

States: waiting/ready, indexing, connected, paused in Play, disconnected, backup saved,
connection failure with a recovery action. Busy controls are actually disabled. Backup
location is selectable read-only text. Dark/light palettes retain explicit labels so
color is never the only signal. Static native controls opt out of movement/scale
animations in this dense utility; press feedback is native and state changes remain
readable under reduced motion. No entrance/stagger effects or marketing sections.

References applied: oil-ui (single component direction, actual evidence), roblox-gui
(content-driven native layout/cleanup), better-ui (consistent surfaces/interaction
states), ui-ux-pro-max (contrast, primary action, platform-native controls). Its generic
landing-page/neumorphism and cyberpunk dataset results did not fit a Studio utility
and were not adopted. The browser installer was removed at the user's request.

Native geometry/state inspection is available through Studio MCP; a rendered native
panel screenshot/independent visual score must be recorded separately if obtained.
Do not present a browser mockup or a viewport capture as proof of dock-widget pixels.
